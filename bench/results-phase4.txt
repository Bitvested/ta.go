Phase 4 performance rewrites — before/after benchmarks.
Hardware: VirtualApple @ 2.50GHz, GOOS=darwin GOARCH=amd64.
Input data: deterministic-seeded random walk from math/rand.
All benches use -count=3, -benchmem.

#1 movingaverages.Sma — running-sum recurrence
================================================
Before:
BenchmarkSma1k-8     31µs/op    135752 B/op    999 allocs/op
BenchmarkSma10k-8   749µs/op   4497270 B/op   9970 allocs/op
BenchmarkSma100k-8   30ms/op 182946100 B/op  99843 allocs/op

After:
BenchmarkSma1k-8     1.5µs/op    8192 B/op    1 allocs/op
BenchmarkSma10k-8     13µs/op   81920 B/op    1 allocs/op
BenchmarkSma100k-8   154µs/op  802822 B/op    1 allocs/op

Speedup: 21× / 58× / 195× (plan target ≥33× at 100k bars).
Alloc count drops from O(n) to 1 (single output slice).

#2 indicators.Rsi — pre-allocated output, hoisted divisor
=========================================================
Before:
BenchmarkRsi1k-8     6.6µs/op    25208 B/op    12 allocs/op
BenchmarkRsi10k-8     75µs/op   357625 B/op    19 allocs/op
BenchmarkRsi100k-8   935µs/op  4101400 B/op    28 allocs/op

After:
BenchmarkRsi1k-8     4.8µs/op     8192 B/op     1 allocs/op
BenchmarkRsi10k-8     48µs/op    81920 B/op     1 allocs/op
BenchmarkRsi100k-8   520µs/op   802820 B/op     1 allocs/op

Speedup: 1.4× / 1.5× / 1.8×. Allocs O(log n) → 1.
Note: the existing Rsi was already a Wilder recurrence (not slice-
rebuilding), so the plan's ≥10× target was anchored to a worse
baseline than ta.go actually had. The remaining wins are pre-alloc
and a hoisted 1/l in a single delta branch per bar.

==============================================================

#4 statistics.Variance — running Σx, Σx²
=========================================
(Plan #4 was framed as "Std SOSQ", but Std is a single-window scalar
function already at O(l). The rolling analog is Variance, which had
the O(n·l) recompute pattern. Optimizing it has the same effect for
chained callers — Bands no longer uses stats.Std after #3, so this
also covers the spirit of the original plan item.)

Before:
BenchmarkVariance10k-8    11ms/op    437236 B/op    9970 allocs/op
BenchmarkVariance100k-8  110ms/op   4901040 B/op   99980 allocs/op

After:
BenchmarkVariance10k-8    16µs/op    81920 B/op       1 allocs/op
BenchmarkVariance100k-8  182µs/op   802820 B/op       1 allocs/op

Speedup: ~680× / ~600×. Allocs O(n/l) → 1.

The new fp form (Σx²/l − mean²) is bit-different from the old
mean-then-deviations form by ~2 ulps; TestVariance now uses
tu.Slice's tolerant comparator (rel/abs 1e-12).

#5 Rolling-extremum cleanups (Aroon, Pr, Elderray, Fisher, Don)
================================================================
AroonUp/AroonDown/Elderray were doing per-window slice copies and
sort.Float64s; Don was building intermediate highs/lows slices.
All converted to single linear scans with no per-window allocation.
Fisher already had a single-pass scan; pre-allocated [][]float64
backing only. Pr was already efficient.

Before / After at 10k bars:
  AroonUp10k     10ms     →  199µs   (≈50×, 89803 → 1 alloc)
  AroonDown10k   8.7ms    →  227µs   (≈38×, 29947 → 1 alloc)
  Elderray10k    4.65ms   →  350µs   (≈13×, 49954 → 2 allocs)
  Don10k         14.5ms   →  558µs   (≈26×, 149735 → 2 allocs)
  Pr10k          232µs    →  276µs   (~unchanged; was already pre-alloc)

Ichimoku and Stoch were left untouched: Ichimoku already matches
the ta.js v2.0.0 per-window scan structure (pre-alloc applies but
is small); Stoch already uses a monotonic deque.
